# 全站 DeepSeek 每日 10 元预算

用户已明确：全部用户合计每天最多 10 元，封顶停止，北京时间次日 00:00 恢复。此次只实现预算保护，不创建云资源、不变更登录策略、不改变旅行路线或酒店策略。

## 实施契约
- 单一付费出口 `model_gateway.create_completion`；攻略链接提取、攻略正文、一句话规划及每次重试都经过该入口。以后新增问答也必须复用。
- 调用前使用 SQLite 条件 UPDATE 原子预留本次费用上限；已计入费用 + 在途预留 + 本次预留不得超过 10 元。不存在先花钱再检查上限的窗口。
- 输出显式设置 max_tokens（原链接提取 8192、新规划沿用 4096）；输入只允许纯文本，以 UTF-8 字节数 + 每条 1024 token 模板余量预留。未知供应商、模型或不支持的输入类型停止调用。
- 按官方当前高峰且输入未命中缓存的费率保守核算，不使用低谷或缓存折扣。现有 deepseek-chat 旧别名已不列在官方当前价格表，保持调用配置，按已公布最高文本模型费率（9 元输入 / 27 元输出，每百万 token）保护，因此实际账单可能更低，可能不足实际 10 元时已暂停。价格表可审查版本在 services/deepseek_pricing.json，服务商调价后需更新。
- 预留和实际返回用量在 `ai_budget_days / ai_usage` 持久化，不存提示词或密钥。金额使用整数纳元，避免浮点误差。
- 正常响应按 usage 的输入 / 输出 token 和保守费率结算，释放多余预留。即使输出格式错误要重试，本次已产生用量也计费；SDK 初始化前失败才释放全部额度。超时、缺失/异常 usage、进程中断保留整笔上限。
- 每次调用按发起请求时的 Asia/Shanghai 日期归属；跨午夜返回仍结算原日期。新日期自然使用新账本，无需定时清零，无结余累积；历史记录保留。重启先处理遗留预留再恢复任务，不能通过重启重置额度。
- 新增只读 `GET /api/v1/ai-budget`：日期、10.00 元上限、已计入上限、预留、剩余、是否可生成、下次重置时间。金额是保守额度账本，非供应商账单。没有公开重置或修改接口。
- 预算不足返回 HTTP 429 和 `AI_DAILY_BUDGET_EXHAUSTED`，页面使用现有错误提示显示恢复时间；已有行程、地图、住宿与导出仍可使用。剩余不足覆盖一次完整请求时可能提前拒绝。

## 范围与迁移
- 仅增加两张表，不改旧行程数据；预算从本次启用时开始记录，之前未计量的历史调用不伪造为已统计。
- 限额只覆盖经本项目服务发起的 DeepSeek 调用，不覆盖其他软件共用同一 Key 的花费、百度地图和云资源费用。
- 当前 SQLite 必须在一个共享持久化磁盘上；多台机器各放一份数据库不能形成全站额度。生产部署须保持统一账本。
- 官方依据：[人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[用量与输出上限](https://api-docs.deepseek.com/api/create-chat-completion/)。2026-09-30 已核对。
