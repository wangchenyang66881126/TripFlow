# 百度交互地图接入说明

## 问题与行为

旧页面直接加载 getscript，浏览器实际报连接中断；组件又在 3 秒后永久切到静态图。现改用百度官方加载器的共享 Promise 和同源 serviceHost，沿用 GL 版本，每个 MapView 创建独立实例。失败提供明确提示与重连；只在失败时展示旧静态预览。

浏览器直连百度脚本失败，但本机 HTTP 客户端能访问。新增固定上游代理，负责 SDK、样式/图片、模块及矢量瓦片；不会代理任意 URL。瓦片从 SDK 原始分片地址映射到固定 0–3 分片 HTTPS 上游，移除仅用于本机代理路由的 is_has_bmap_proxy 标志；二进制瓦片不按其误标的 text/javascript 类型进行文本转换。

## 文件与配置

- frontend/src/lib/baidu-map.ts：官方 @baidumap/jsapi-loader 1.0.0，GL、25秒超时，按需加载，同页单实例加载器。
- frontend/src/components/MapView.tsx：每日独立实例、生命周期清理、容器缩放适配、编号弹窗、全览与缩放控制、失败重连。
- backend/app/api/baidu_map.py：同源资源代理，15秒上游超时、8MiB响应上限、固定上游和路径校验、统一错误。
- backend/app/core/config.py：优先从根 .env 的 BAIDU_JSAPI_AK 读取；本机兼容已有 frontend/.env.local 的 VITE_BAIDU_JSAPI_AK。与服务端 BAIDU_MAP_AK 严格分开。
- 浏览器端 AK 由后端注入上游请求，并从脚本内容移除；前端构建不再引用 VITE_BAIDU_JSAPI_AK。
- 新资源接口访问日志只记录路径，避免记录 SDK 临时签名。

## 新资源接口约定

GET /api/v1/baidu-map/{path}，查询参数沿用百度 SDK 请求；ak 由后端覆盖为浏览器端 AK，不接受客户端提供的其他上游地址。允许 api/getscript/getmodules、res/images 资源、监测入口及 tiles/0–3/pvd|starpic。

成功：200，按真实上游返回 JavaScript/CSS/图片/瓦片内容及 Content-Type。静态 res 资源可缓存，含动态配置的 SDK及服务响应不缓存。
失败：统一 {"error":{"code":"MAP_CONFIG|MAP_RESOURCE|MAP_QUERY|MAP_UPSTREAM|MAP_HOST","message":"可读说明"}}，分别使用 503/404/400/502 等状态，不向客户端传递上游地址、密钥或堆栈。
