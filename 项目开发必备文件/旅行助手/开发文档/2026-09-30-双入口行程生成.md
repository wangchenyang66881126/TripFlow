# 双入口行程生成（本地功能子阶段）

用户希望访客既能粘贴攻略，也能输入一句话生成自己的行程。本子阶段先打通输入能力；公网账号方式、预算与云资源待用户答复，尚未执行部署。

## 适配与契约
- 延续 Vite / React / FastAPI / SQLite，不替换现有地图、酒店、导航与长图服务。
- `POST /api/v1/trips` 保留 `source_link` 字段，新增可选 `mode: guide | idea`（默认 guide）。输入 1–12000 字；全空白拒绝。返回原有 `trip_id/task_id`；错误维持统一结构。
- guide 中的小红书链接走原链路，分享文案由后端取出链接；纯文字走攻略地点抽取。idea 根据自然语言规划。当前文字能力为单城市 1–7 天，未给天数时建议 2 天并明确展示。
- 新任务种类 guide / plan；状态沿用 created → parsing → awaiting_confirm → routing → done。模型不产生坐标，由百度地图核对；核对失败的地点保留并要求处理 / 跳过。
- 两种新入口统一使用 DeepSeek JSON 契约，Pydantic 校验；最多调用 2 次（配置上限 3），SDK 无隐式重试；超时 60 秒、输出 4096 tokens 可配置。缺目的地等返回 NEEDS_INPUT，不当作服务失败重试。
- 结构化模型结果、用量与版本原子写入 `data/assets/<trip>/plan.json`；逐点状态存 SQLite。新任务在重启时续跑，复用已有模型结果和地点。模型尚未产生检查点时重启可能再次调用，正式上线需要队列与全局预算控制。
- 前端输入切换、提交锁、错误保留原文、刷新恢复任务状态；地点仍需确认后才调用现有路线服务。

## 验证与边界
- 自动化：纯文本和想法分流、旧链接兼容、缺城市、格式错误/超时/初始化失败、有限重试、输入长度、断点续跑不重复模型和地点。
- 真实验证：一句话、攻略正文各跑一条真实 DeepSeek → 百度 POI → 保存 → 确认 → 路线；桌面与手机检查；重启验证保存结果。
- 本地版本仍无账号隔离和用户配额，不可作为公开服务直接上线。既有分享只读问题、旧链接抓取恢复与外部图像授权需在公网发布前处理。
- 邀请码内测 / 开放注册，已有云资源与域名：已询问用户，待答复。创建计费云资源前提供具体费用并确认。
